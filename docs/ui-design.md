# Fashion-Agent Web UI 设计方案

## 1. 文档信息

- 项目名称：Fashion-Agent
- 文档类型：Web 视觉、布局、组件与交互规范
- 文档状态：第一版设计方案
- 更新日期：2026-08-03
- 设计范围：桌面 Web 优先，同时保证手机浏览器可用

本文档定义 Fashion-Agent 的界面形态和交互体验。
[前端界面技术方案](./frontend.md)负责说明前端如何实现，本文件负责说明界面
应该呈现什么、如何组织以及用户如何操作。

品牌气质、颜色、字体、图片和图形语言见
[Fashion-Agent Web 视觉方向](./visual-direction.md)。

本文档不创建前端代码，不代表字体、图标或组件库已经下载。

---

## 2. 设计定位

### 2.1 设计概念

界面采用“个人衣橱工作台 + 编辑式时尚杂志”的组合方向：

- 像个人工具一样清晰、高效；
- 像穿搭编辑内容一样具有呼吸感和品质感；
- 不做商品瀑布流，不营造促销和冲动消费氛围；
- 不使用强性别化的粉色或蓝色作为默认品牌表达；
- AI 是协助者，不用机器人形象抢占主要视觉。

### 2.2 体验关键词

```text
清爽 / 可信 / 年轻 / 克制 / 可执行 / 个性化
```

### 2.3 界面设计原则

1. **先给穿搭结论**：用户首先看到可以怎么穿，再按需展开理由和来源；
2. **已有衣橱优先**：衣橱单品比商品入口拥有更高视觉优先级；
3. **不确定性可见**：候选不足、天气缺失和识别不确定必须明确显示；
4. **一次一个主动作**：一个区域只突出一个主要按钮；
5. **内容不伪装成事实**：通用建议、已有衣物和真实商品具有不同标签；
6. **隐私默认收敛**：不在首页暴露详细尺码、偏好来源和完整历史反馈；
7. **桌面高效、移动可用**：桌面用于主要开发和演示，手机仍能完成核心流程。

## 3. Web 优先的响应式策略

第一版以桌面浏览器为主要开发和演示环境，但不是固定宽度桌面站点。

| 屏幕范围 | 主要形态 | 导航方式 |
|---|---|---|
| `≥ 1280px` | 三栏工作台 | 左侧导航 + 主内容 + 上下文侧栏 |
| `1024–1279px` | 两栏工作台 | 左侧导航 + 主内容，侧栏改抽屉 |
| `768–1023px` | 紧凑 Web | 窄侧栏或顶部导航 |
| `< 768px` | 单列 Web | 顶部标题 + 底部导航 |

桌面端不应简单放大手机页面。衣橱筛选、Outfit 对比和档案编辑需要充分利用
横向空间；聊天正文仍应保持适合阅读的最大宽度。

## 4. 品牌视觉系统

### 4.1 色彩

整体使用偏暖中性色，主色使用深松绿色，强调“衣橱、材质、可持续与可信赖”。

| Token | 建议色值 | 用途 |
|---|---|---|
| `canvas` | `#F6F3EE` | 页面背景 |
| `surface` | `#FFFFFF` | 内容面板、表单和浮层 |
| `surface-subtle` | `#ECE8E1` | 次级区域和悬停状态 |
| `text-primary` | `#202522` | 标题与主要正文 |
| `text-secondary` | `#626A65` | 说明、时间和辅助信息 |
| `border` | `#D8D3CB` | 分隔线和输入框边界 |
| `brand` | `#315E52` | 主要操作、选中状态和品牌识别 |
| `brand-hover` | `#264B42` | 主按钮悬停状态 |
| `accent` | `#A85D3B` | 少量重点提示，不作为大面积背景 |
| `success` | `#287552` | 可用、完成和成功 |
| `warning` | `#8A6200` | 风险和需注意事项 |
| `danger` | `#A43C3C` | 删除、阻断错误和危险操作 |
| `info` | `#366A8A` | 知识来源和中性信息 |

要求：

- 品牌色不能用来表示所有状态；
- 状态必须同时使用图标和文字；
- 重要正文与背景的对比度至少达到 WCAG AA；
- 图片丰富的卡片上不直接覆盖长文字，应提供独立文字区域；
- 不使用大面积高饱和渐变制造“AI 感”。

### 4.2 字体

第一版优先使用系统字体，避免额外字体下载和中文缺字：

```text
Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif
```

| 层级 | 建议规格 | 用途 |
|---|---|---|
| Display | 32/40，500 | 页面主要欢迎语，仅少量使用 |
| H1 | 28/36，500 | 页面标题 |
| H2 | 22/30，500 | 页面区块标题 |
| H3 | 18/26，500 | 卡片标题 |
| Body | 16/26，400 | 正文、聊天内容 |
| Small | 14/21，400 | 标签说明、辅助信息 |
| Caption | 12/18，400 | 时间、来源和极次要信息 |

正文不小于 14px。金额、温度和计数使用等宽数字特性，避免列表跳动。

### 4.3 间距与形状

- 基础间距：4px；
- 常用间距：8、12、16、24、32、48px；
- 输入框和普通按钮高度：40px；
- 核心发送按钮和移动端主操作：44–48px；
- 内容卡片圆角：12px；
- 浮层和主要 Outfit 卡片圆角：16px；
- 标签圆角：999px；
- 阴影仅用于浮层、抽屉和悬浮状态，普通卡片优先使用边框。

### 4.4 图标和图片

- 使用统一线性图标体系；
- 不使用 Emoji 作为唯一功能图标；
- 衣物图片默认使用 `4:5` 竖向比例；
- Outfit 封面在没有真实合成图时使用单品拼图，不生成虚假上身效果；
- 图片缺失时使用带品类名称的中性占位图；
- 用户头像不得根据姓名或偏好推断性别形象。

## 5. 全局应用框架

### 5.1 桌面布局

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ Fashion-Agent                                      帮助   用户菜单      │
├──────────────┬──────────────────────────────────────┬───────────────────┤
│              │                                      │                   │
│  智能搭配    │              主内容区                │   上下文侧栏      │
│  我的衣橱    │                                      │   天气 / 衣橱     │
│  我的穿搭    │         最大阅读宽度 760–880          │   本轮条件 / 来源 │
│  风格档案    │                                      │                   │
│              │                                      │                   │
│  设置        │                                      │                   │
│              │                                      │                   │
├──────────────┴──────────────────────────────────────┴───────────────────┤
│ 仅在必要页面出现的状态或错误提示                                        │
└─────────────────────────────────────────────────────────────────────────┘
```

- 顶栏高度建议 64px；
- 左侧导航宽度建议 224px；
- 右侧上下文栏宽度建议 300–336px；
- 主内容宽度随页面变化，聊天保持窄，衣橱列表可以更宽；
- 右侧栏没有内容时直接隐藏，不保留空白栏。

### 5.2 导航

导航顺序：

1. 智能搭配；
2. 我的衣橱；
3. 我的穿搭；
4. 风格档案；
5. 设置。

导航项使用图标、文字和明确选中背景。不要增加“商城”一级导航；未来真实商品能力
仍应从穿搭缺口或用户明确购物请求进入。

### 5.3 页面标题区

统一结构：

```text
页面标题
一句简短说明                         [次要操作] [主要操作]
```

页面标题区不放统计卡片。首页不需要“衣服总数、Outfit 总数、AI 使用次数”等
与当前任务无关的仪表盘指标。

## 6. 智能搭配页

智能搭配是默认首页，也是产品核心。

### 6.1 空会话状态

```text
┌──────────────────────────────────────────────────────────┐
│                                                          │
│              今天想为哪个场景搭配？                      │
│      告诉我场景、天气或你想穿的某件衣服即可开始。        │
│                                                          │
│  [明天通勤怎么穿] [周末约会] [从衣橱搭一套]             │
│                                                          │
│  ┌────────────────────────────────────────────────────┐  │
│  │ 输入你的穿搭需求……                         [发送] │  │
│  └────────────────────────────────────────────────────┘  │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

快捷提示只是可编辑的输入起点，不应点击后立即发送。避免默认提示全部导向购物。

### 6.2 对话状态

```text
┌──────────────────────────────────────────────────────────────┐
│ 新建会话                                           结束会话 │
├──────────────────────────────────────────────────────────────┤
│                                               [用户消息]     │
│                                                              │
│ [Agent 说明文本]                                             │
│                                                              │
│ ┌────────────── 本轮穿搭方案 ──────────────────────────────┐ │
│ │ 清爽夏季通勤                                             │ │
│ │ [简约] [通勤]                                适合 26–31℃ │ │
│ │                                                          │ │
│ │ 上装  浅蓝色亚麻衬衫        [我的衣橱]                  │ │
│ │ 下装  深灰直筒西裤            [我的衣橱]                  │ │
│ │ 鞋履  白色简洁运动鞋          [我的衣橱]                  │ │
│ │                                                          │ │
│ │ 推荐理由……                                              │ │
│ │ [查看替代单品] [注意事项]                  [保存这套穿搭] │ │
│ └──────────────────────────────────────────────────────────┘ │
│                                                              │
│ 知识依据 · 3 个来源                              [展开]      │
├──────────────────────────────────────────────────────────────┤
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ 继续补充条件或告诉我想调整哪一件……             [发送] │ │
│ └──────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

### 6.3 消息样式

- 用户消息靠右，使用低饱和品牌浅色背景；
- Agent 消息靠左，不需要头像气泡，使用自然正文排版；
- 结构化 Outfit 独立成卡片，不嵌在长文本气泡内；
- 连续 Agent 说明不重复显示名称和图标；
- 消息时间默认隐藏，需要时在悬停或详情中显示；
- Agent 回复按纯文本或受控 Markdown 渲染，不允许任意 HTML。

### 6.4 输入区

第一版输入区包含：

- 多行文本框；
- 天气/日期上下文入口；
- 发送按钮；
- 当前请求中的简短状态。

规则：

- Enter 发送、Shift+Enter 换行；
- 请求进行中禁止同一会话再次发送；
- 文本达到上限前显示剩余字符提醒；
- 不能使用假流式动画逐字展示已完整返回的内容；
- 客户端停止等待时只显示“已停止在本页等待”，不能声称服务端已取消。

### 6.5 Outfit 卡片

视觉层级：

1. 方案名称和场景；
2. 核心单品；
3. 来源标签；
4. 推荐理由；
5. 替代项、缺口和注意事项；
6. 保存操作。

来源标签固定为：

- `我的衣橱`：深松绿色标签；
- `外部商品`：蓝灰信息标签；
- `建议单品`：中性描边标签。

只有真实商品数据且存在原始链接时，才显示“查看来源平台”。不使用“立即购买”。

### 6.6 衣橱缺口

缺口不能做成红色错误页，应作为可解决的计划展示：

```text
还缺少 1 个核心单品

鞋履
当前没有可用鞋履，暂时无法形成完整 Outfit。

[去衣橱补充] [调整要求]
```

只有 `shopping_search_allowed=true` 且 `next_actions` 包含 `search_products` 时，
才显示“帮我搜索商品”。

### 6.7 风险提示

- `warning`：黄色提示条，方案仍可查看；
- `error`：红色提示条，明确说明为何不能作为可执行 Outfit；
- 风险要靠稳定错误码选择图标和标题，具体说明显示服务端 `message`；
- 同一问题不要在文本、卡片顶部和底部重复三次。

### 6.8 右侧上下文栏

仅显示本轮有用内容：

- 日期和天气；
- 已识别场景；
- 当前明确偏好；
- 是否允许购物；
- 知识来源。

不显示完整 Style Profile，也不让用户误以为临时条件已经永久保存。窄屏下改为
“本轮条件”抽屉。

## 7. 我的衣橱页

### 7.1 列表布局

```text
我的衣橱                                      [拍照识别] [新增衣物]
管理可以参与穿搭的衣物。

[全部品类 ▼] [全部状态 ▼] [搜索名称]                    24 件

┌────────────┐ ┌────────────┐ ┌────────────┐ ┌────────────┐
│  衣物图片  │ │  衣物图片  │ │  衣物图片  │ │  衣物图片  │
│            │ │            │ │            │ │            │
├────────────┤ ├────────────┤ ├────────────┤ ├────────────┤
│ 亚麻衬衫   │ │ 直筒西裤   │ │ 白色球鞋   │ │ 羊毛大衣   │
│ 浅蓝 · M   │ │ 深灰 · 30  │ │ 白 · 42    │ │ 驼色 · L   │
│ ● 可用  ⋯  │ │ ● 可用  ⋯  │ │ ○ 暂不可用│ │ ● 可用  ⋯  │
└────────────┘ └────────────┘ └────────────┘ └────────────┘
```

桌面端默认卡片网格，可提供紧凑列表切换，但第一版不必同时实现两种视图。

### 7.2 衣物卡片

卡片内容：

- 图片或品类占位图；
- 名称；
- 主颜色、尺码；
- 当前状态；
- 更多操作菜单。

状态切换应支持快速操作，但从 `available` 切为 `unavailable` 时可提供可选说明：
“待洗、未干、损坏或其他”。这些说明保存到备注，不增加后端状态枚举。

### 7.3 新增与编辑

桌面端使用右侧抽屉，手机端使用全屏页面。字段按认知顺序分组：

1. 名称和品类；
2. 图片；
3. 颜色、材质和尺码；
4. 风格、季节和场景；
5. 状态和备注。

名称与品类为首屏重点。可选字段不要同时铺满页面，应使用“补充更多信息”展开。

### 7.4 图片识别确认

识别结果使用左右对照：桌面左侧图片，右侧可编辑草稿。低置信度字段使用
“请确认”标签，不把 AI 预测值直接标记为错误。

底部操作：

```text
[取消]                               [确认并加入衣橱]
```

确认按钮只有在名称、品类等后端必填条件满足后可用。

### 7.5 空状态

```text
衣橱还是空的
先添加几件常穿衣物，Fashion-Agent 才能优先用已有衣服搭配。

[新增第一件衣物]   [拍照识别]
```

不在空状态直接展示商品广告。

## 8. 我的穿搭页

### 8.1 列表页

顶部筛选：场景、仅收藏。卡片重点显示：

- Outfit 名称；
- 场景、季节和风格；
- 三件核心单品摘要；
- 收藏状态；
- 是否已有反馈。

没有合成穿搭图时使用简洁的单品文字或缩略图组合，不生成未经实现的模特效果图。

### 8.2 详情页

桌面使用双栏：

```text
┌────────────────────────────┬────────────────────────────────┐
│ 单品组合与来源             │ 清爽夏季通勤                   │
│                            │ 通勤 · 简约 · 夏季             │
│ 上装 ……                    │                                │
│ 下装 ……                    │ 推荐理由                       │
│ 鞋履 ……                    │ ……                             │
│                            │                                │
│                            │ [收藏] [提供反馈]              │
└────────────────────────────┴────────────────────────────────┘
```

当前后端没有删除 Outfit 接口，因此不要显示删除按钮。

### 8.3 反馈

使用底部弹层或对话框：

- 喜欢；
- 不喜欢；
- 可选文字说明。

用户可以只写文字。提交后说明：“反馈会帮助产生待确认的偏好候选，不会自动修改
你的长期档案。”

## 9. 风格档案页

### 9.1 页面结构

```text
风格档案
这里保存你明确确认的长期偏好。

┌───────────────────────────────┐
│ 我的明确偏好                  │
│ 喜欢的风格  [简约] [通勤]     │
│ 避免的风格  [高饱和街头]      │
│ 喜欢的颜色  [黑] [米白]       │
│ 避免的颜色  [荧光绿]          │
│ ……                            │
│                    [保存修改] │
└───────────────────────────────┘

待确认偏好（2）
┌───────────────────────────────┐
│ 你可能更喜欢“宽松版型”        │
│ 来自 3 次已反馈 Outfit         │
│              [暂不处理] [确认]│
└───────────────────────────────┘

偏好来源与有效期                         [查看]
```

### 9.2 标签输入

- 已保存值使用可删除 Chip；
- 输入时提供常用建议，但允许自由文本；
- 喜欢与避免发生冲突时，在冲突标签附近就地提示；
- 清空数组需要用户明确删除全部 Chip；
- PATCH 只提交实际修改字段，不能用未加载的空值覆盖档案。

### 9.3 候选确认

候选卡片必须展示：

- 偏好方向；
- 值和类别；
- 支持证据数量；
- 反向证据数量；
- “确认后会保存到长期档案”的说明。

确认操作不能预选，也不能批量静默确认。

### 9.4 偏好来源

偏好来源使用表格或时间列表显示：

- 偏好内容；
- 来源类型；
- 确认时间；
- 有效期；
- 设置过期和删除。

删除单条偏好前说明它将同时移除该来源对档案的影响。

## 10. 设置与隐私页

第一版包含：

- 当前开发身份说明；
- 新建/结束当前会话；
- 数据与隐私说明；
- 删除风格档案；
- 动画和显示偏好；
- 版本、健康状态和问题诊断入口。

`request_id` 只在错误详情中显示“复制诊断编号”，不长期展示在正常页面。

删除风格档案是高风险操作，使用明确确认对话框：

```text
删除风格档案？
这会删除你明确保存的长期偏好和相关偏好来源，不会删除衣橱和已保存穿搭。

[取消] [删除风格档案]
```

不要提供尚未实现的“删除整个账户”按钮。

---

## 11. 通用组件规范

### 11.1 按钮

| 类型 | 使用场景 | 示例 |
|---|---|---|
| Primary | 当前区域唯一主操作 | 发送、保存这套穿搭 |
| Secondary | 次要但常用操作 | 新增衣物、调整要求 |
| Ghost | 低强调操作 | 展开来源、取消 |
| Danger | 明确破坏性操作 | 删除衣物、删除档案 |
| Icon | 空间受限且含可访问名称 | 收藏、更多菜单 |

禁用按钮必须同时解释原因，不能只降低透明度。

### 11.2 标签

标签分为：

- 来源标签；
- 风格和场景标签；
- 状态标签；
- 风险标签。

同一标签不能同时承担筛选按钮和只读状态展示。可点击筛选需要具有明显交互状态。

### 11.3 表单

- 标签始终可见，不只依赖 placeholder；
- 必填和可选字段明确标注；
- 错误紧邻字段，顶部可提供错误摘要；
- 保存中禁止重复提交；
- 服务端返回 409 时保留用户已输入内容；
- 金额使用文本或十进制定向控件，不使用浮点计算；
- 日期时间输入明确时区。

### 11.4 Toast 与页面消息

- Toast 只用于短暂成功信息，例如“已收藏”；
- 表单错误、业务缺口和 503 不能只放 Toast；
- 关键错误在操作区域持续显示；
- 每个错误提供可执行下一步；
- 有 `X-Request-ID` 时允许复制诊断编号。

### 11.5 Skeleton 与加载

- 列表使用与实际卡片尺寸接近的 Skeleton；
- 聊天使用一个自然语言加载状态，不模拟已经生成的文字；
- 超过合理等待时间后显示“仍在处理中”；
- Loading 不应让已有内容全部消失；
- 页面切换时优先保留缓存数据并显示轻量刷新状态。

---

## 12. 空、错、禁用和降级状态

每个主要页面都必须设计以下状态：

| 状态 | 表达方式 |
|---|---|
| 首次空数据 | 解释价值 + 一个主操作 |
| 筛选无结果 | 保留筛选条件 + 清除筛选 |
| 网络断开 | 保留当前内容 + 手动重试 |
| 401/403 | 引导重新认证，不暴露数据 |
| 404 | 说明资源不存在或无权访问 |
| 409 | 保留编辑内容并指出冲突字段 |
| 422 | 字段级错误 |
| 503 | 服务暂不可用 + 诊断编号 + 稍后重试 |
| Agent 无完整方案 | 使用结构化 Outfit Gap，不显示虚假 Outfit |
| 知识无结果 | 正常回答中说明依据不足，不伪造来源 |
| 图片识别失败 | 保留本地预览，允许重试或手动录入 |

---

## 13. 动效

动效只用于解释状态变化：

- 抽屉和弹窗：160–220ms；
- 卡片展开：160ms；
- 收藏状态：轻微缩放或颜色变化，不使用持续动画；
- 新消息出现：轻微位移，不逐字模拟流式；
- Skeleton：低对比度渐变，避免高频闪烁。

启用 `prefers-reduced-motion` 时关闭非必要动画。

---

## 14. Web 可访问性规范

- 页面具有唯一 H1；
- 侧栏、主内容和底部导航使用语义区域；
- 跳转到主内容链接可被键盘访问；
- 对话新回复使用克制的 `aria-live` 通知；
- 弹窗打开后焦点进入，关闭后返回触发按钮；
- 卡片本身不全部做成按钮，内部操作保持独立焦点；
- 图标按钮必须具有可访问名称；
- 图片识别的不确定字段不能只靠黄色表示；
- 输入错误与字段通过 `aria-describedby` 关联；
- 触控目标至少约 44×44px；
- 所有核心流程都能仅使用键盘完成；
- 在 200% 缩放下不丢失内容和操作。

---

## 15. 文案语气

Fashion-Agent 使用平等、具体、不过度亲昵的语气。

推荐：

- “这套搭配更适合 28℃ 左右的通勤场景。”
- “当前衣橱没有可用鞋履，因此还不能形成完整 Outfit。”
- “确认后，这条偏好会保存到你的长期档案。”

避免：

- “你必须这样穿。”
- “这绝对适合所有人。”
- “猜你是女生，所以推荐……”
- “完美显瘦”“遮住缺陷”等身体羞辱式表达；
- “立即抢购”“最后机会”等促销式措辞。

## 16. 首批原型范围

在创建正式前端工程前，建议先完成以下高保真或可点击原型：

1. 智能搭配空状态；
2. 对话 + 完整 Outfit；
3. 对话 + Outfit Gap；
4. 衣橱列表；
5. 新增衣物抽屉；
6. 图片识别草稿确认；
7. Outfit 列表与详情；
8. 反馈对话框；
9. 风格档案；
10. 偏好候选确认；
11. 503 和字段错误状态；
12. 手机端聊天与底部导航。

第一批原型使用 Mock 数据，不调用真实 LLM、数据库、Chroma、Redis 或图片模型。

## 17. UI 实施优先级

### UI-0：设计基础

- 字体、间距、圆角和图标规范；
- 应用框架与响应式导航；
- 按钮、输入框、标签、弹窗和错误状态。

### UI-1：核心穿搭闭环

- 聊天空状态和对话状态；
- Outfit、Gap、Issue 和来源；

### UI-2：衣橱与 Outfit 管理

- 衣橱列表、详情和编辑；
- 图片识别确认；
- Outfit 列表、详情、收藏和反馈。

### UI-3：个性化与上线准备

- 风格档案和偏好来源；

## 18. UI 验收标准

1. 用户进入首页后能在 5 秒内识别主要输入入口；
2. Outfit 中已有衣物、商品和通用建议可以不依赖颜色区分；
3. 衣橱缺口不会被误解成已经找到的商品；
4. 桌面端能高效完成衣橱筛选与档案编辑；
5. 手机浏览器能完成聊天、新增衣物和查看 Outfit；
6. 加载、空数据、422、404、409 和 503 均有对应界面；
7. 删除操作明确说明影响范围并二次确认；
8. 图片识别结果必须经过用户确认才能入库；
9. 核心交互支持键盘和 200% 缩放；
10. 页面不显示未实现的支付、自动购买、商品商城或账户删除功能。

## 19. 开始制作界面前需要确认

当前方案可以直接支持线框图和组件开发，但正式确定视觉稿前建议确认：

1. 是否接受“暖中性 + 深松绿”的品牌方向；
2. 第一版是否需要深色模式；
3. 是否已有 Logo，还是先使用纯文字标识；
4. 衣物图片是否由用户提供，还是第一版主要使用占位图；
5. 是否需要 Outfit 视觉拼图；
6. 第一版是否展示图片识别入口；
7. 是否需要公开分享 Outfit；
8. 第一版主要演示分辨率。

未确认的视觉偏好不影响前端架构和 Mock 数据准备，但应在制作高保真页面前确定，
避免实现后进行大面积视觉返工。
