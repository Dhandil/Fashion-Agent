# Fashion-Agent Web 视觉方向

## 1. 文档信息

- 项目名称：Fashion-Agent
- 文档类型：品牌与产品视觉方向
- 文档状态：第二版，已用于 Web MVP
- 更新日期：2026-08-10
- 适用范围：Web、响应式页面及未来 PWA

本文档回答“Fashion-Agent 应该给用户什么视觉感受”。它是
[Web UI 设计方案](./ui-design.md)的上游依据，不规定具体前端实现方式。

本文档不包含外部图片、商业字体或需要下载的设计资产。

---

## 2. 视觉方向结论

Fashion-Agent 第一版推荐采用：

> **年轻衣橱手账（Young Closet Journal）**

它把“个人衣橱工具”的实用性与年轻人的穿搭笔记、衣物吊牌和每日搭配卡结合起来。
界面应当首先让人想到“这是我的衣橱”，其次才是“这里有一个 AI”。

整体感觉应当是：

```text
温暖但不甜腻
时尚但不高冷
年轻但不幼稚
智能但不炫技
个性化但不越界
克制购物，强调穿搭
```

### 2.1 一句话视觉描述

> 像一本会理解天气和场景、也会越用越懂你的私人衣橱手账。

### 2.2 希望用户产生的第一印象

1. 这是帮助我决定怎么穿的工具；
2. 它关心我的衣橱和实际场景；
3. 页面专业但没有距离感；
4. 它不会不断推销商品；
5. 我的个人信息在这里会被谨慎对待。

---

## 3. 为什么选择这一方向

Fashion-Agent 的核心不是商城，而是穿搭决策、衣橱管理和长期偏好理解。
因此视觉设计需要同时满足：

- 能承载较长的 Agent 解释；
- 能清晰展示衣物图片和 Outfit 结构；
- 能高效管理衣橱和档案表单；
- 不让商品卡片成为视觉中心；
- 不通过性别刻板颜色限定用户；
- 不通过强烈“AI 发光效果”掩盖数据真实性。

暖色中性背景降低管理工具的冰冷感；清晰的靛蓝提供年轻、可靠且不带性别暗示的主识别，
珊瑚橙只作为衣物标签、划线和场景提示。点阵纸纹理、虚线缝线和吊牌孔等细节建立
“私人衣橱手账”的独有记忆点，同时不影响长对话与表单的可读性。

### 3.1 外部案例提炼

本方向只提炼产品规律，不复制案例的具体画面：

- [Clickdrobe](https://clickdrobe.com/)把“今日穿搭、天气和已有衣物”放在同一决策画面中，说明首页应展示当天任务，而不是解释 AI 能力；
- [Dayclo](https://dayclo.app/)持续强调“让已有衣橱重新被使用”，与 Fashion-Agent 的衣橱优先边界一致；
- [Indyx](https://www.myindyx.com/home)把数字衣橱视为个人风格资产，而不是商品目录；
- 不对称卡片只用于首页这种优先级不同的内容，衣橱列表仍保留等尺寸网格，避免降低衣物间的可比较性。

因此首页采用“主问题 + 今日衣橱画板 + 场景快捷入口”的不对称结构；衣橱、穿搭列表和表单仍使用稳定、可扫描的规则布局。

## 4. 备选方向比较

| 方向 | 特征 | 优点 | 当前不作为主方向的原因 |
|---|---|---|---|
| 黑白高端时尚 | 大面积黑白、衬线标题、强留白 | 高级、编辑感强 | 容易显得疏离，对日常衣橱管理不够亲切 |
| 年轻社交潮流 | 高饱和色、贴纸、动态卡片 | 活泼、传播性强 | 容易像时尚社区或购物 App，干扰理性决策 |
| 年轻衣橱手账 | 暖中性、靛蓝、珊瑚橙、衣物标签 | 有个人感、年轻、兼顾工具与时尚 | 当前推荐方向 |
| 未来 AI 科技 | 深色、霓虹、渐变、发光 | AI 特征明显 | 容易喧宾夺主，不适合衣物真实来源与隐私表达 |

未来如果产品转向公开时尚内容或社交社区，应重新评估；当前阶段不需要在多个方向
之间混合使用视觉语言。

## 5. 品牌性格

### 5.1 品牌是

- 清晰的；
- 尊重用户的；
- 有审美但讲依据的；
- 关注现实约束的；
- 鼓励使用已有衣物的；
- 对购物保持克制的；
- 对错误和不确定性诚实的。

### 5.2 品牌不是

- 强势的时尚权威；
- 促销导购；
- 身材评价者；
- 性别和身份推断者；
- 用术语包装普通建议的 AI；
- 用动画和渐变吸引注意的科技展品。

## 6. 视觉关键词与情绪板描述

### 6.1 核心关键词

```text
自然材质 / 晨间光线 / 有序衣橱 / 手账网格
衣物吊牌 / 今日搭配卡 / 真实衣物 / 轻松但有条理
```

### 6.2 情绪板应包含

- 自然光下的真实衣物细节；
- 亚麻、棉、羊毛等可感知纹理；
- 整洁但仍有生活感的个人衣橱；
- 现代杂志与穿搭手账结合的文字层级和网格；
- 米白、靛蓝、珊瑚橙和少量状态色；
- 不同风格、年龄和表达方式的衣物，而非单一人群模板。

### 6.3 情绪板应避免

- 电商大促红、倒计时和折扣标签；
- 霓虹渐变、全息材质和大面积发光；
- 过度精修或不真实的模特图；
- 只出现单一性别或单一身材的穿搭；
- 奢侈品秀场作为唯一视觉参考；
- 大面积粉色、紫色或蓝色承担性别暗示；
- 没有来源的 AI 虚拟试衣图。

正式制作情绪板时，外部图片必须确认授权和使用范围。

## 7. 核心色彩系统

### 7.1 主色板

| 名称 | 色值 | 角色 |
|---|---|---|
| 手账米白 | `#F7F6F1` | 全局画布，提供纸张与生活感 |
| 纯白 | `#FFFFFF` | 内容表面、表单和浮层 |
| 墨水蓝黑 | `#25283A` | 主要文字，代替绝对黑色 |
| 铅笔灰 | `#6B6E7D` | 辅助文字与次要说明 |
| 淡雾紫灰 | `#DDDDE6` | 分隔线、输入框和低强调边界 |
| 衣橱靛蓝 | `#4856C8` | 品牌色、主要操作和选中状态 |
| 深靛蓝悬停 | `#3945A8` | 主按钮悬停和按下状态 |
| 珊瑚橙 | `#FF7657` | 标签、划线、编号和少量年轻化强调 |

### 7.2 功能色

| 状态 | 色值 | 使用方式 |
|---|---|---|
| 成功/可用 | `#4F7662` | 图标、状态文字和浅色提示背景 |
| 警告/注意 | `#9A681F` | 风险提示，必须配合图标和标题 |
| 错误/危险 | `#B44747` | 阻断错误和删除操作 |
| 信息/来源 | `#3F6F9C` | 知识来源、外部数据和中性提示 |

### 7.3 色彩比例

建议使用近似比例：

```text
60% 暖米白和空白画布
30% 白色表面、文字和中性边界
10% 品牌色、功能色与少量强调
```

这不是每个页面必须机械遵守的数字，而是防止品牌色和状态色占据过多视觉空间。

### 7.4 已验证的主要对比度

| 组合 | 对比度 | 结果 |
|---|---:|---|
| `#25283A` / `#F7F6F1` | 13.45:1 | 适合正文和标题 |
| `#6B6E7D` / `#F7F6F1` | 4.67:1 | 适合普通辅助文字 |
| 白色 / `#4856C8` | 6.10:1 | 适合主按钮文字 |
| 白色 / `#3945A8` | 8.11:1 | 适合悬停和按下状态 |
| 白色 / `#B44747` | 5.34:1 | 适合危险按钮文字 |

其他颜色组合在实现时仍需逐项验证。浅色功能背景不能直接复用主功能色作为小号正文，
必须检查实际对比度。

### 7.5 色彩使用边界

- 衣橱靛蓝用于主操作，而不是所有可点击内容；
- 珊瑚橙只作标签、划线、编号和少量视觉强调，不与错误色混用；
- 衣橱可用状态不能只显示绿色圆点；
- Outfit 来源类型必须同时显示文字；
- 不使用彩虹渐变表示 AI 正在工作；
- 商品入口不能使用比 Outfit 主操作更醒目的颜色。

---

## 8. 字体方向

### 8.1 字体选择原则

- 中文长文本清晰；
- 系统字体优先，避免首屏字体下载；
- 字重克制，只使用常规与中等字重；
- 不用纤细时尚字体显示重要信息；
- 数字、金额和温度保持易比较。

第一版建议：

```text
Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif
```

如果未来希望增强杂志感，可以只在短标题中评估一款具有授权的中文标题字体，
正文和表单仍使用无衬线字体。

### 8.2 排版性格

- 页面标题简短、有呼吸感；
- Agent 正文使用自然段，不做夸张聊天气泡；
- Outfit 名称可以略大，但不能像广告标题；
- 标签保持简短，不塞入完整句子；
- 知识来源和诊断信息降低层级，但不能小到难以阅读。

---

## 9. 图形、边界和表面

### 9.1 形状语言

- 主要卡片使用 12–16px 圆角；
- 普通输入框和按钮使用 8–10px 圆角；
- 标签使用胶囊形；
- 分隔主要依靠留白和细边框；
- 阴影只用于浮层和层级变化；
- 不使用大量玻璃拟态和半透明毛玻璃。

整体应显得柔和但不软弱。所有元素都使用超大圆角会显得像儿童或社交应用，
不符合专业穿搭助手定位。

### 9.2 卡片风格

普通卡片：

```text
白色表面 + 细暖灰边框 + 12px 圆角 + 无阴影
```

核心 Outfit：

```text
白色表面 + 16px 圆角 + 更充分留白 + 清晰标题层级
```

悬浮抽屉和弹窗：

```text
白色不透明表面 + 轻微阴影 + 明确焦点层级
```

卡片不能层层嵌套。推荐理由、注意事项和来源优先通过标题、分隔和留白组织。

---

## 10. 图片与摄影方向

### 10.1 衣物图片

- 使用真实用户衣物图片；
- 以自然光和中性背景为优先；
- 列表统一使用 4:5 比例裁切；
- 详情页允许查看完整图片；
- 不对用户衣物自动进行改变颜色或材质的美化；
- 图片不存在时显示品类占位，而不是随机网络图片。

### 10.2 Outfit 展示

第一版不依赖虚拟模特图。可以使用：

- 单品缩略图组合；
- 单品名称和来源组成的编辑式列表；
- 后续经过确认的平铺拼图。

不能使用生成式模特图暗示真实上身效果，也不能让建议单品看起来像用户已经拥有。

### 10.3 商品图片

商品图片只能来自真实商品工具返回的来源。应与平台名称和外部链接一起展示，
不能为了页面完整使用知识库或占位图冒充商品图。

### 10.4 人物摄影

如果未来使用人物图片，应体现不同性别表达、肤色、身材和风格。图片用于表达场景，
不能作为系统推断用户身份、身材或适合风格的依据。

---

## 11. 图标与插画

### 11.1 图标

- 使用统一的 1.5–2px 线性图标；
- 图标端点和圆角保持一致；
- 图标默认继承文字颜色；
- 操作图标必须配合可见文字或可访问名称；
- 收藏可以使用星形或心形，但同一产品只能固定一种；
- AI 能力可以使用小型星芒符号，但不作为 Logo 主体。

### 11.2 插画

插画只适用于空状态和首次引导，建议采用：

- 单色或双色线性图；
- 衣架、衣橱、折叠衣物和 Outfit 轮廓；
- 少量材质纹理；
- 不出现夸张机器人或聊天机器人吉祥物。

插画不能替代操作说明，也不能占据超过主要任务入口的视觉面积。

---

## 12. AI 的视觉表达

Fashion-Agent 不需要通过霓虹、渐变和机器人头像证明自己是 AI。

AI 状态通过内容和行为表达：

- “正在分析本轮条件”；
- “正在检查可用衣橱”；
- “正在检索知识依据”；
- “当前信息不足，需要确认”。

界面规则：

- 不模拟未实现的逐字流式输出；
- 不展示虚假的思考过程；
- 不展示模型内部推理；
- 不使用持续旋转的 AI 星芒吸引注意；
- 不把模型输出和权威数据库事实使用相同标签；
- 对降级和不确定结果使用明确文本。

---

## 13. 各页面的视觉应用

### 13.1 智能搭配

- 暖米白画布；
- Agent 正文接近编辑文章，不使用厚重气泡；
- Outfit 使用最完整的白色内容表面；
- 输入区保持稳定、简洁；
- 右侧本轮条件使用低强调中性色；
- 知识来源使用信息蓝而不是品牌主色。

### 13.2 我的衣橱

- 图片成为卡片第一视觉；
- 名称、颜色和状态层级清楚；
- 筛选区域保持工具感；
- 不让每件衣物使用不同彩色边框；
- 不可用衣物可以降低图片饱和度，但仍必须显示文字状态。

### 13.3 我的穿搭

- 更接近编辑式作品集合；
- Outfit 名称和场景高于收藏、反馈等操作；
- 不使用价格标签和购买角标；
- 没有合成图时保持诚实的单品组合展示。

### 13.4 风格档案

- 使用清晰表单和 Chip，不做人格测试式娱乐界面；
- 候选偏好使用柔和信息表面；
- 已确认偏好和系统候选视觉上明显区分；
- 删除和过期属于低频管理动作，不抢占主界面。

---

## 14. 动效方向

动效关键词：

```text
自然 / 短暂 / 有因果 / 可关闭
```

推荐：

- 抽屉自然滑入；
- Outfit 内容展开；
- 收藏状态轻微变化；
- 筛选结果平稳更新；
- 新消息轻微进入。

避免：

- 大面积粒子和流光；
- 长时间循环呼吸动画；
- 内容加载时页面整体跳动；
- 为普通操作播放庆祝动画；
- 逐字模拟不存在的流式响应。

全部非必要动效响应 `prefers-reduced-motion`。

---

## 15. Logo 与产品标识建议

第一版建议先使用文字标识：

```text
Fashion-Agent
```

文字标识使用主文字色，允许用一个非常克制的衣架、衣橱门或组合关系图形作为
辅助符号。Logo 不使用购物袋、购物车或价格标签，避免把产品误解为商城。

在正式 Logo 完成前：

- 不使用临时网络 Logo；
- 不把 Emoji 当作正式标识；
- 不为了填充顶栏设计复杂品牌动画；
- 浏览器图标可以先使用单字母 `F` 的品牌色占位版本。

---

## 16. 文案与视觉的配合

视觉应让语气显得专业而平等。

| 场景 | 推荐表达 | 避免表达 |
|---|---|---|
| 生成成功 | “这套搭配可以直接从你的衣橱完成。” | “完美穿搭已生成！” |
| 候选不足 | “当前缺少可用鞋履。” | “生成失败。” |
| 商品入口 | “查看来源平台” | “立即抢购” |
| 图片识别 | “这些字段需要你确认。” | “AI 已准确识别。” |
| 偏好候选 | “你可能更偏好宽松版型。” | “AI 发现你就是宽松风格。” |
| 身材相关 | 使用用户主动提供的中性描述 | “遮肉、显瘦、修饰缺陷” |

---

## 17. 深色模式决策

第一版建议先完善浅色主题，不把深色模式作为前端起步的阻塞项。

原因：

- 衣物图片和材质判断在浅色中性背景下更稳定；
- 当前需要优先验证信息结构和核心交互；
- 深色模式不是简单反转颜色，需要重新检查图片、状态色和对比度；
- 同时实现两套视觉会增加初期组件验收成本。

设计 Token 应保留主题扩展能力。若后续加入深色模式，应单独设计深灰绿画布，
不能使用纯黑背景和高亮霓虹色。

---

## 18. 视觉 Do / Don't

### Do

- 让真实衣物图片成为衣橱页面重点；
- 使用留白组织长回复和 Outfit；
- 通过来源标签解释数据身份；
- 对风险和缺口提供明确下一步；
- 保持表单、列表和对话使用同一设计语言；
- 用低饱和色支持长时间使用。

### Don't

- 把首页做成商品推荐瀑布流；
- 使用大面积紫蓝 AI 渐变；
- 用颜色推断或暗示用户性别；
- 用虚拟模特图冒充真实试穿；
- 使用过多卡片和统计数字填满页面；
- 把每个功能都设计成高强调按钮；
- 让装饰性动画盖过 Agent 正文；
- 用知识内容冒充真实商品。

---

## 19. 视觉验收清单

视觉稿进入前端实现前，应确认：

1. 第一眼能看出产品以穿搭而非购物为核心；
2. 品牌色没有覆盖所有交互和状态；
3. 已有衣物、商品和建议单品不依赖颜色也能区分；
4. 页面没有性别刻板视觉暗示；
5. Outfit 比商品入口具有更高视觉优先级；
6. 长文本在桌面与手机上都具有合适行宽；
7. 空状态、风险和错误没有使用羞辱或责备语气；
8. 主要文字、按钮和状态颜色通过对比度检查；
9. 200% 缩放后内容不会重叠；
10. 动效关闭后全部功能仍可理解；
11. 图片缺失时不会显示误导性的随机图片；
12. 未实现功能没有出现在正式视觉稿中。

## 20. 当前需要用户确认的视觉决策

开始高保真 Web 页面前，需要最终确认：

1. 是否接受“年轻衣橱手账”作为主方向；
2. 是否接受手账米白、衣橱靛蓝与珊瑚橙作为主色组合；
3. 是否先使用纯文字 Logo；
4. 第一版是否暂不实现深色模式；
5. Outfit 第一版是否使用单品组合而非虚拟模特图；
6. 衣橱缺少图片时是否接受品类文字占位图。

这些决策确认后，页面原型、组件 Token 和前端样式应以本文档为统一视觉基准，
避免在不同页面临时选择互相冲突的颜色、圆角和图片风格。
